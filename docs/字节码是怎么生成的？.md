# 字节码是怎么生成的？

## 输入

已通过语义分析的 AST + 符号表。

## 输出

`BytecodeProgram` — 包含：
- `code`：`vector<uint8_t>`，字节码流
- `constants`：`vector<int>`，整数常量池
- `strings`：`vector<string>`，字符串常量池
- `functions`：`vector<FunctionInfo>`，函数表

## 流程

`BytecodeGenerator::generate(Program &ast)` 驱动 visitor 遍历 AST：

### 1. `visit(Program)` — 布局

```
addFunction("fib", 1)       // 注册函数到函数表
addFunction("主函数", 0)
JMP 0                       // 占位，稍后 patch
  (fib 函数体)
  (主函数 函数体)
patch JMP → 跳过函数体     // entryPos
CALL 主函数
HALT
```

### 2. `visit(Function)` — 函数框架

```
funcInfo.codeOffset = getCodeSize()  // 记录函数起始位置
enterScope()
allocateSlot(params...)             // 参数占槽位
node.body->accept(*this)            // 生成函数体
ICONST 0; RET                       // 默认返回值
// 立即扫描是否含 CALL，更新 isLeaf
```

### 3. 语句/表达式 → 指令映射

| AST 节点 | 发射的字节码 |
|----------|-------------|
| `NumberLiteral(42)` | `ICONST const_idx` |
| `Identifier(x)` | `LOAD slot` |
| `a = b` | `... b ... STORE slot; LOAD slot` |
| `a + b` | `... a ... b ... ADD` |
| `a - 1` | `... a ... SUB_ICONST 1`（超级指令） |
| `喵叫(x)` | `... x ... PRINT` |
| `fib(args)` | `... args ... CALL funcIdx` |
| `如果 cond 那么 {t} 否则 {e}` | `... cond ... JIF → t; JMP → e` |
| `当 cond 那么 {body}` | `标记; ... cond ... JIF → 结束; ... body ... JMP ← 标记` |

### 4. 常量折叠（编译期优化）

当二元操作符的左右操作数均为 `NumberLiteral` 时，直接计算并发射 `ICONST`，跳过运行时计算。

### 5. 编译期递归求值（-Ofast）

当 `CallExpr` 的目标函数全为纯整数算术（无 STORE/PRINT/SCONST）且参数全为字面量时，用栈模拟器在编译期递归执行函数体，直接发射 `ICONST result`。带记忆化缓存，上限 10M 次调用。

## 指令编码

每条指令：
- **1 字节** opcode（0x00–0x15）
- **4 字节** 操作数（可选），小端序

`hasOperand(op)` 返回 true 的指令：`ICONST` `SCONST` `JMP` `JIF` `LOAD` `STORE` `CALL` `SUB_ICONST` `GT_ICONST`
