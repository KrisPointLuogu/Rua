# 工作流程 05 — 错误处理

> Rust 版把 C 版的「error_at 打印即 exit」改成全链路 `Result` 传播。
> 本篇说明错误模型、各阶段错误清单与行号覆盖情况。

## 一、错误模型：RuaError + Result

```rust
// ast.rs
pub struct RuaError { pub line: usize, pub msg: String }
pub type Result<T> = std::result::Result<T, RuaError>;
```

- 每个可能出错的函数返回 `Result<T>`，出错处用 `rua_err!(line, "…")`
  或 `?` 向上传播；
- main() 统一收尾：`eprintln!("{}", e)` 输出「第 N 行：消息」到
  stderr，`exit(1)`；
- 正常结束退出码 0；无参数时打印用法并 exit(1)（与 C 版一致）。

与 C 版的关键差异：**错误是值，不是控制流跳转**——
中途可以携带行号、可以组合、测试友好。

## 二、词法阶段错误（lexer.rs）

| 消息 | 触发场景 | 行号 |
| --- | --- | --- |
| 无法识别的字符 | 非法符号（如单独的 `!`）、未知字节 | 出错行 |
| 字符串未闭合 | 引号后到文件尾都没等到配对引号 | 起始行 |

## 三、语法阶段错误（parser.rs）

| 消息 | 触发场景 | 行号 |
| --- | --- | --- |
| 语法错误：期望的符号不匹配 | expect() 校验失败 | 当前 Token 行 |
| 语法错误：期望标识符 | 该出现名字的地方不是标识符 | 当前 Token 行 |
| 语法错误：期望表达式 | 表达式位置遇到关键字/界符 | 当前 Token 行 |
| 只能调用函数 | `(` 跟在非标识符表达式后 | 节点行 |
| 数组长度必须是数字 | 数组声明 `[]` 内不是数字字面量 | 当前 Token 行 |

另有入口层错误（main.rs）：无法打开文件、文件不是有效的 UTF-8
（行号固定 0）。

## 四、运行时错误（runtime.rs / vm.rs）

### 4.1 函数调用相关

| 消息 | 触发场景 | 行号 |
| --- | --- | --- |
| 未定义的函数 | find_fn 找不到 | 调用节点行 |
| 函数参数数量不匹配 | 实参个数 ≠ 形参个数 | 调用节点行 |
| 未定义的变量 | env_get 沿链找不到 | **引用节点行** |

### 4.2 类型与运算相关

| 消息 | 触发场景 | 行号 |
| --- | --- | --- |
| 运算需要数字 | `-` `*` 等混入字符串 | **运算节点行** |
| 不能除以 0 / 不能取模 0 | 除数/模数为 0 | **运算节点行** |
| 比较需要数字 | `< > <= >=` 混入字符串 | 运算节点行 |
| 该变量不是数组 | 对非数组下标访问/赋值 | 下标节点行 |
| 数组下标越界 | 下标为负或 ≥ 长度 | 下标节点行 |
| 赋值目标无效 | 赋值左侧既非变量也非下标 | 目标节点行 |

VM 层的除/模指令自带行号（`Inst::Div(u32)`），报错文案与解释层一致；
字节码里没有的类型错误不会出现在 VM 路径（判定层已排除字符串等）。

## 五、与 C 版的行号差异

C 版 `env_get` / `apply_binop` 的签名里没有行号，部分运行时错误
固定输出「第 0 行」。Rust 版所有 AST 节点自带 line 字段，
一路传进环境与运算层——**运行时错误全部带精确行号**。
这是移植时的有意改进（两版输出在正确程序上逐字节一致，
仅在出错路径上 Rust 版更精确）。

## 六、JIT 路径的差异

JIT 生成的机器码不含任何检查代码（为了快）：

- 除 0 → CPU `#DE` 异常 → SIGFPE 终止进程（无「第 N 行」消息）；
- JIT 判定本身拒绝数组/全局引用/字符串运算，所以越界类、类型类
  错误不会出现在 JIT 路径；
- 同一份程序在默认（JIT）与 `--no-jit` 下死法可能不同——
  这是性能换安全的已知取舍，与 C 版行为一致。
