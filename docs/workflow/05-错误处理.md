# 工作流程 05 — 错误处理

> 全项目只有一条报错通道：`error_at()`。本篇说明它的行为、
> 各阶段的错误清单，以及行号覆盖情况。

## 一、统一出口：error_at（utf8.h）

```c
error_at(msg, line)
  ├─ fprintf(stderr, "第 %d 行：%s\n", line, msg)
  └─ exit(1)
```

- **直接终止进程**，不做错误恢复、不返回调用方；
- 输出走 stderr，程序正常输出（stdout）不受污染；
- 退出码恒为 1；正常结束为 0。

## 二、词法阶段错误（lexer.h）

| 消息 | 触发场景 |
| --- | --- |
| 无法识别的字符 | 非法符号（如单独的 `!`）、未知字节 |
| 字符串未闭合 | 引号后到文件尾都没等到配对引号 |

行号：均为出错时的真实行号。

## 三、语法阶段错误（parser.h）

| 消息 | 触发场景 |
| --- | --- |
| 语法错误：期望的符号不匹配 | expect() 校验失败（缺括号/花括号等） |
| 语法错误：期望标识符 | 该出现名字的地方不是标识符 |
| 语法错误：期望表达式 | 表达式位置遇到关键字/界符等 |
| 只能调用函数 | `(` 跟在非标识符表达式后 |
| 数组长度必须是数字 | 数组声明 `[]` 内不是数字字面量 |

行号：取当前 Token 的行号，定位精确。

## 四、运行时错误（runtime.h）

### 4.1 函数调用相关

| 消息 | 触发场景 | 行号 |
| --- | --- | --- |
| 未定义的函数 | find_fn 找不到 | 调用节点行号 |
| 函数参数数量不匹配 | 实参个数 ≠ 形参个数 | 调用节点行号 |
| 参数过多 | 实参 > 64 | 调用节点行号 |
| 未定义的变量 | env_get 沿链找不到 | **0** |

### 4.2 类型与运算相关

| 消息 | 触发场景 | 行号 |
| --- | --- | --- |
| 运算需要数字 | `-` `*` 或拼接外的 `+` 混入字符串 | **0** |
| 不能除以 0 / 不能取模 0 | 除数/模数为 0 | **0** |
| 比较需要数字 | `< > <= >=` 混入字符串 | **0** |
| 未知运算符 | bin_table 空槽（理论不可达） | **0** |

### 4.3 数组相关

| 消息 | 触发场景 | 行号 |
| --- | --- | --- |
| 该变量不是数组 | 对非数组下标访问/赋值 | 下标节点行号 |
| 数组下标越界 | 下标为负或 ≥ 长度 | 下标节点行号 |
| 赋值目标无效 | 赋值左侧既非变量也非下标 | 目标节点行号 |

## 五、行号为 0 的原因

带行号的错误都发生在「拿着 AST 节点」的地方（节点里有 line 字段）；
而 `env_get` / `apply_binop` 系列只收到变量名或 Value 值，
**签名里没有行号**，于是固定传 0。输出形如：

```
第 0 行：未定义的变量
```

这是已知的设计妥协：要精确定位需把行号贯穿进环境与运算层。

## 六、JIT 路径的差异

JIT 生成的机器码**不含任何检查代码**（为了快）：

- 除 0 → CPU `#DE` 异常 → SIGFPE 终止进程（无「第 N 行」消息）；
- JIT 判定本身拒绝数组/全局引用，所以越界类错误不会出现在 JIT 路径；
- 解释器路径则全部走 error_at 正常报错。

同一份程序在 `make interp` 与 `make` 下可能死法不同——
这是性能换安全的已知取舍。
