# 工作流程 02 — 词法与语法分析

> 源码字符串如何变成 Token 流，再长成 AST。
> 涉及 src/lexer.rs、src/parser.rs、src/ast.rs。

## 一、前置：UTF-8 与错误通道

- Rust 的 `char` 就是 Unicode 码点，`src.chars()` 天然按码点迭代，
  不需要 C 版 utf8.h 那样的手工变长解码——中文关键字直接按字符比对；
- 报错不再「打印即退出」：词法/语法阶段返回
  `Err(RuaError { line, msg })`，由 main() 统一格式化（见 05-错误处理.md）。

## 二、词法分析（lexer.rs）

### 2.1 数据结构

```rust
pub struct Token { pub kind: TokenKind, pub text: String,
                   pub num: i64, pub line: usize }
```

中文关键字映射成 `TK_` 前缀枚举：
`喵→TK_MIAO 变量→TK_BIAN 如果→TK_RUGUO 那么→TK_NAME 否则→TK_FOUZE
当→TK_DANG 返回→TK_FANHUI 喵叫→TK_MIAOJIAO 数组→TK_SHIZU`。

### 2.2 主循环：lex_all → lex_next

```
lex_all(src) -> Result<Vec<Token>>
   └─ 循环 lex_next() 直到 TK_EOF，收集进 Vec
```

`lex_next` 每次跳过空白与注释后识别一个 Token，判定顺序：

```
看当前字符 c0
 ├─ None            → TK_EOF
 ├─ 空白/换行        → 跳过（换行时 line+=1）继续循环
 ├─ '#'             → 注释：#* … *# 多行 / # … 单行，跳过后继续循环
 ├─ '0'~'9'         → 十进制累加 → TK_NUM
 ├─ 标识符字符       → 切出完整单词 → keyword_kind() 查关键字表
 │                     命中 → 对应 TK_*；未命中 → TK_IDENT
 ├─ " ' “ ‘          → lex_string() 字符串字面量
 └─ 其余             → 运算符 match；不认识 → Err(无法识别的字符)
```

标识符字符集：英文字母/数字/下划线/常用汉字（U+4E00~U+9FA5）。

双字符运算符靠 peek 两个 char 区分：`== != >= <=` 与单字符 `= > <`；
`!` 后面不是 `=` 直接报错。

### 2.3 字符串字面量：lex_string

- 支持两对引号：英文 `"" ''` 与中文全角 `“” ‘’`
  （起始引号决定结束引号）；
- 仅英文引号内支持转义：`\n \t \r \\ \" \'`；全角引号内 `\` 是普通字符；
- 内容逐字符收集进 String；未闭合 → `Err(字符串未闭合)`。

## 三、语法分析（parser.rs）

### 3.1 分析器状态与基础动作

```rust
pub struct Parser { toks: Vec<Token>, pos: usize }
peek()    看当前类型（不前进）
advance() 取走当前 Token 并前进
expect(k) 要求当前是 k 否则 Err(语法错误…)
expect_ident() 要求标识符并返回名字
```

入口 `Parser::parse_tokens(toks) -> Result<(Node, Vec<Node>)>`：
返回 `(程序节点, 函数定义列表)`——**函数不进程序体**，
由调用方（Runtime::build）注册进函数表。

### 3.2 表达式：优先级爬升

二元运算符优先级表 `op_prec()`（数字越大越优先，同级左结合）：

| 优先级 | 运算符 |
| --- | --- |
| 1 | `==` `!=` |
| 2 | `>` `<` `>=` `<=` |
| 3 | `+` `-` |
| 4 | `*` `/` `%` |

```
parse_expr(ps)                 入口：先爬升，再看有没有 = 赋值
   parse_expr_prec(ps, 1)      优先级爬升主循环
      left = parse_primary()
      循环: peek 的运算符优先级 ≥ min_prec？
        → advance 吃掉运算符
        → right = parse_expr_prec(prec+1)   (+1 保证左结合)
        → 包成 Node::Binary
```

赋值不在优先级表里，而是 `parse_expr` 在爬升结束后补一刀：
`目标 = 表达式` 构造成 `Node::Assign`（目标是变量或数组下标）。

### 3.3 原子表达式与后缀循环：parse_primary

原子：`Node::Num` / `Node::Str` / `( 表达式 )` / `Node::Ident` /
`喵叫(…)`（直接构造成 Call）。

之后进入后缀循环，反复吃两种后缀：

- `(` 实参列表 `)` —— 只允许跟在标识符后（函数调用）；构造成 `Node::Call`；
- `[ 下标 ]` —— 构造成 `Node::Index`（base + 下标）。

所以 `a[1]`、`f(x)[2]` 这类链式后缀都能正确嵌套。

### 3.4 语句分发：parse_statement

```
peek 类型        解析函数        产物
TK_BIAN    →  parse_var      →  Node::Var     变量 名 = 表达式
TK_SHIZU   →  parse_array    →  Node::Array   数组 名[长度] = { 广播初值 }
TK_RUGUO   →  parse_if       →  Node::If      如果 条件 那么? { } 否则? { }
TK_DANG    →  parse_while    →  Node::While   当 条件 那么? { }
TK_FANHUI  →  parse_return   →  Node::Return  返回 表达式?
其余       →  parse_expr     →  表达式语句（赋值/调用等）
```

细节：

- `那么` 是可选引导词；`否则` 分支可选；
- `返回` 后面紧跟 `}` 或 EOF 视为无返回值；
- 数组长度必须是数字字面量，`{}` 里恰好一个表达式（广播填充）。

### 3.5 AST 形态（ast.rs）

C 版是「一个结构体 + kind 复用字段」；Rust 版直接用枚举，
各节点只带自己需要的字段，非法状态不可表示：

```rust
pub enum Node {
    Num { val, line },  Str { val, line },  Ident { name, line },
    Var { name, init, line },  Array { name, len, fill, line },
    Assign { target, value, line },  Index { base, index, line },
    Binary { op, left, right, line },  Call { name, args, line },
    If { cond, then_blk, else_blk, line },  While { cond, body, line },
    Return { value, line },  Block { stmts, line },  Prog { stmts },
    Func { name, params, body, line },
}
```

每个节点都带 `line`（报错定位），一路传到运行时。

## 四、产物形态

以这段源码为例：

```
喵 加(a, b) {
    返回 a + b
}
喵叫(加(1, 2))
```

`parse_tokens` 返回：

```
fns[0] = Func { name:"加", params:["a","b"], body: Block{ Return{ Add{a,b} } } }

prog = Prog { stmts:[ Call{ "喵叫", [ Call{ "加", [Num 1, Num 2] } ] } ] }
```
