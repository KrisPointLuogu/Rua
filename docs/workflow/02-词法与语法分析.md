# 工作流程 02 — 词法与语法分析

> 源码字符串如何变成 Token 流，再长成 AST。
> 涉及 includes/utf8.h、includes/lexer.h、includes/parser.h。

## 一、前置：UTF-8 基础（utf8.h）

Rua 的关键字和标识符都是中文，源码按 UTF-8 处理：

- `Char` 是 `uint32_t`，表示一个 Unicode 码点；
- `utf8_peek(p)` 读当前位置码点、`utf8_advance(&p)` 前进一个码点，
  屏蔽 1~4 字节变长编码细节；
- `is_ident_char(c)`：英文字母/数字/下划线/常用汉字（U+4E00~U+9FA5）
  可作标识符字符——这是「喵」「变量」能当关键字被切出来的前提；
- `error_at(msg, line)`：全项目统一的报错出口（见 05-错误处理.md）。

## 二、词法分析（lexer.h）

### 2.1 数据结构

```
Token { kind, text, num, line }
  kind  TokenKind 枚举
  text  标识符名 / 字符串内容（其余为 NULL）
  num   数字字面量的值（仅 TK_NUM）
  line  行号（报错定位用）
```

中文关键字映射成 `TK_` 前缀枚举：
`喵→TK_MIAO 变量→TK_BIAN 如果→TK_RUGUO 那么→TK_NAME 否则→TK_FOUZE
当→TK_DANG 返回→TK_FANHUI 喵叫→TK_MIAOJIAO 数组→TK_SHIZU`。

### 2.2 主循环：lex_all → lex_next

```
lex_all(src)
   └─ 循环 lex_next(&lx) 直到 TK_EOF，收集进动态数组
```

`lex_next` 每次跳过空白与注释后识别一个 Token，判定顺序：

```
读一个字符 c0
 ├─ '\0'            → TK_EOF
 ├─ 空白/换行        → 跳过（换行时 line++）继续循环
 ├─ '#'             → 注释：#* … *# 多行 / # … 单行，跳过后继续循环
 ├─ '0'~'9'         → 十进制累加 → TK_NUM
 ├─ 标识符字符       → 切出完整单词 → keyword_kind() 查关键字表
 │                     命中 → 对应 TK_*；未命中 → TK_IDENT（带 text）
 ├─ " ' “ ‘          → lex_string() 字符串字面量
 └─ 其余             → 单字符/双字符运算符 switch；不认识 → error_at
```

双字符运算符靠向前多看一个字符（`lx->p[1]`）区分：
`== != >= <=` 与单字符 `= > <`；`!` 后面不是 `=` 直接报错。

### 2.3 字符串字面量：lex_string

- 支持两对引号：英文 `"" ''` 与中文全角 `“” ‘’`
  （起始引号决定结束引号，如 `“` 配 `”`）；
- 仅英文引号内支持转义：`\n \t \r \\ \" \'`；
  全角引号内 `\` 是普通字符；
- 内容逐码点拷进倍增缓冲区，结束时产出 `TK_STR`（text 为 malloc 字符串）；
- 未闭合（遇到 `\0`）→ `error_at("字符串未闭合", line)`。

## 三、语法分析（parser.h）

### 3.1 分析器状态与基础动作

```
Parser { toks, n, pos }      纯下标推进，不改 Token 数组
peek()    看当前类型（不前进）
advance() 取走当前 Token 并前进
expect(k) 要求当前是 k 否则 error_at("语法错误…")
expect_ident() 要求标识符并返回 strdup 的名字
```

### 3.2 表达式：优先级爬升

二元运算符优先级表 `op_prec()`（数字越大越优先，同级左结合）：

| 优先级 | 运算符 |
| --- | --- |
| 1 | `==` `!=` |
| 2 | `>` `<` `>=` `<=` |
| 3 | `+` `-` |
| 4 | `*` `/` `%` |

```
parse_expr(ps)                 入口：先爬升，再看有没有 = 赋值
   parse_expr_prec(ps, 1)      优先级爬升主循环
      left = parse_primary()
      循环: peek 的运算符优先级 ≥ min_prec？
        → advance 吃掉运算符
        → right = parse_expr_prec(prec+1)   (+1 保证左结合)
        → 包成 N_BINARY 节点
```

赋值不在优先级表里，而是 `parse_expr` 在爬升结束后补一刀：
`目标 = 表达式` 构造成 `N_ASSIGN`（目标是变量或数组下标）。

### 3.3 原子表达式与后缀循环：parse_primary

原子：`N_NUM` / `N_STR` / `( 表达式 )` / `N_IDENT` / `喵叫(…)`（直接构造成 N_CALL）。

之后进入后缀循环，反复吃两种后缀：

- `(` 实参列表 `)` —— 只允许跟在标识符后（函数调用），否则报
  「只能调用函数」；构造成 `N_CALL`；
- `[ 下标 ]` —— 构造成 `N_INDEX`（left=基表达式，right=下标）。

所以 `a[1]`、`f(x)[2]` 这类链式后缀都能正确嵌套。

### 3.4 语句分发：parse_statement

```
peek 类型        解析函数        产物
TK_BIAN    →  parse_var      →  N_VAR     变量 名 = 表达式
TK_SHIZU   →  parse_array    →  N_ARRAY   数组 名[长度] = { 广播初值 }
TK_RUGUO   →  parse_if       →  N_IF      如果 条件 那么? { } 否则? { }
TK_DANG    →  parse_while    →  N_WHILE   当 条件 那么? { }
TK_FANHUI  →  parse_return   →  N_RETURN  返回 表达式?
其余       →  parse_expr     →  表达式语句（赋值/调用等）
```

细节：

- `那么` 是可选引导词（有就吃掉，没有也行）；`否则` 分支可选；
- `返回` 后面紧跟 `}` 或 EOF 视为无返回值（left 为空，运行期补 0）；
- 数组长度必须是数字字面量，`{}` 里恰好一个表达式（广播填充）。

### 3.5 代码块与函数定义

- `parse_block`：`{ 语句* }` → `N_BLOCK`（语句动态数组）；
- `parse_function`：`喵 名字(形参, …) { 体 }` → `N_FUNC`
  （str=名字，params/nparams=形参表，body=函数体块）。

### 3.6 顶层分拆（rua.c 的 compile）

```
while (peek != TK_EOF) {
    if (peek == TK_MIAO)  register_fn(parse_function());  // 进函数表
    else                  prog->stmts += parse_statement(); // 进程序体
}
```

**函数定义不进入程序语句列表**——它们在编译期就注册进全局
`fn_table`，运行期通过 `find_fn()` 按名字调用。程序体只含顶层语句。

## 四、产物形态

以这段源码为例：

```
喵 加(a, b) {
    返回 a + b
}
喵叫(加(1, 2))
```

编译完成后内存里同时存在：

```
fn_table[0] = Fn{ name="加", params=["a","b"], body=N_BLOCK{ 返回 a+b } }

prog (N_PROG)
  └─ stmts[0] = N_CALL "喵叫"
        └─ args[0] = N_CALL "加"
              └─ args = [N_NUM 1, N_NUM 2]
```
