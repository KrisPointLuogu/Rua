# 工作流程 04 — 快路径：JIT 与字节码 VM

> 纯整数函数的两级加速：默认走 x86-64 JIT，`--no-jit` 或不可 JIT 时
> 走字节码 VM。涉及 src/jit.rs、src/vm.rs、runtime.rs 的分流点。

## 一、共享判定：scan_function

两个引擎共用同一个预扫描入口 `vm::scan_function(params, body)`，
保证「可 VM」与「可 JIT」的口径一致：

1. **节点白名单**：只允许 Num/Ident/Binary/Call/Var/Assign/If/While/
   Return/Block；Str 仅允许作 `喵叫` 实参；Array/Index 一律拒绝；
2. **引用检查**：所有 Ident 必须是形参或函数内 `变量` 声明的局部变量，
   引用全局变量 → 拒绝；
3. **闭包传播**（迭代到不动点）：调用了不可编译的函数 → 自己也不可。

在此之上：

- **可 VM** = 通过 scan_function（无参数个数上限，放宽到 64）；
- **可 JIT** = 可 VM && 形参 ≤6 && `cfg!(x86_64 + linux)`。

预编译在 `Runtime::build` 里一次完成：

```
Runtime::build(&fns, jit_enabled)
  ├─ vm::compile_functions(&fns)   → VmEngine（字节码 + 函数索引表）
  └─ jit::compile_functions(&fns)  → JitEngine（机器码 + 地址表）
```

## 二、字节码 VM（vm.rs）

### 2.1 指令集（栈机）

```rust
enum Inst {
    Push(i64), PushStr(Rc<String>),
    LoadVar(u32), StoreVar(u32),          // 局部槽读写
    Add, Sub, Mul, Div(u32), Mod(u32),    // 除/模带行号（报错用）
    Eq, Ne, Gt, Lt, Ge, Le,
    Jmp(usize), Jz(usize),                // 控制流
    Call(usize, u8),                      // 用户函数（引擎索引+实参个数）
    CallPrint(u8),                        // 内置 喵叫
    Ret, Pop,
}
```

### 2.2 编译：两遍

1. 预扫描（scan_function）分配局部槽位、收集被调函数；
2. 给可 VM 函数按序分配索引 → 逐个生成字节码
   （递归/互调经索引表引用，编译期即可解析）。

### 2.3 执行：invoke

```
vm::invoke(engine, idx, args)
  └─ 帧栈模拟：
      Call     压新帧（形参入槽、局部槽补 0）
      Ret      弹帧，结果压回调用方栈顶
      CallPrint 弹 n 个实参打印（无分隔符、末尾换行）
      Div/Mod  除 0 → Err(第 N 行：不能除以 0)
```

比树遍历快约 2~3 倍：没有 AST 节点分发与环境链查找，
但仍是逐条解释字节码。

## 三、x86-64 JIT（jit.rs）

### 3.1 为什么快

把整段函数体一次性翻译成原生指令，运行期只剩寄存器/栈操作。
对递归/循环密集的程序比 VM 快一个数量级以上
（fib(36)：JIT 0.16s vs VM 3.0s）。

### 3.2 变量编号与寄存器映射

分析阶段给每个变量（形参+局部）分配连续 vreg 号，临时值按表达式结构
续编——计数顺序与代码生成顺序严格一致。

vreg 到物理寄存器是固定映射（Linux x86-64 / SysV）：

```
VREG_TO_PHYS = { RAX, RBX, R12, R13, R14, R15, RSI, RDI, RDX,
                 RCX, R8, R9, R10, R11 }
  v0  = RAX   结果累加器（返回值也走它）
  v1~v6 形参（序言里从 ABI 参数寄存器拷入）
  v7~v13 其余临时/局部
  v14+ 溢出：放栈槽 [rbp - k*8]
```

### 3.3 帧布局（序言/尾声）

```
序言                          尾声
push rbp                      add rsp, frame_bytes
mov  rbp, rsp                 pop callee-saved…（逆序）
push 用到的 callee-saved      pop rbp
sub  rsp, frame_bytes         ret
xor  eax, eax                 ← 无显式返回时默认返回 0
拷贝形参 ABI 寄存器 → v1..vP
```

- callee-saved（RBX、R12~R15）被映射占用就必须 push/pop 保护；
- 16 字节栈对齐：`(pushed_bytes + frame_bytes) ≡ 8 (mod 16)` 反推帧大小；
- 含调用/打印/除模的函数额外分配 caller-saved 快照槽：
  调用前把活跃值快照进槽，调用后恢复。

### 3.4 两遍编译与函数地址表

```
jit::compile_functions(&fns)
  ├─ mmap 匿名 RWX 可执行内存（代码缓冲 1MB）+ 数据区（字符串字面量）
  ├─ 第一遍：逐个 plan（复用 scan_function 判定）+ 闭包传播
  ├─ 占位：可 JIT 函数在地址表写非零哨兵
  └─ 第二遍：逐个发射机器码，真实地址写回表与 Function.jit
```

生成的代码不直接 call 目标地址，而是「movabs 表地址 → mov [表+idx*8]
→ call reg」——递归/互调在运行期查表，天然正确。

### 3.5 表达式 → 机器码

统一约定「求值结果放进 dst vreg」：

- 数字：mov imm32（大数 movabs）；变量：vreg 间 mov（溢出槽读内存）；
- 二元运算：左操作数进 RAX——`add/sub/imul`；`/ %` 走 cqo+idiv
  （先快照 caller-saved，算完恢复，取模再 mov rax,rdx）；
  比较走 cmp + setcc + movzx；
- 调用：实参装入 ABI 参数寄存器 → 表间接 call → 结果从 RAX 存回 dst。

### 3.6 函数内喵叫

字符串字面量集中放在 JIT 数据区（判重后追加），机器码直接取地址；
整数实参先经 `jit_itoa` 格式化到全局 scratch 再打印：

```
jit_print(msg, endl)   #[no_mangle] extern "C"，fputs ×2
  endl = "\n"（末参） 或 ""（非末参，无分隔符）
```

输出规则与解释器/VM 逐字节一致。

## 四、调用点分流回顾

```
exec_call()
  ① jit_enabled && f.jit？ → jit::invoke   （Value.num 补齐 6 个 i64 调用）
  ② f.vm？                 → vm::invoke    （Result<i64>，除 0 报错带行号）
  ③ 树遍历解释                              （完整语义）
```

已知差异：JIT 内除 0 由 CPU 触发 SIGFPE 终止进程（VM/解释层正常报错）；
非 x86-64 平台 JIT 整体禁用，自动降为 VM/解释。
