# 工作流程 04 — 快路径：x86-64 JIT

> 纯整数函数如何从 AST 直接编译成机器码，以及解释器如何在调用点分流。
> 涉及 includes/jit.h 与 includes/jit/ 四个分文件（仅 `OPTIMIZATION` 构建生效）。

## 一、为什么快

解释器每执行一个节点都要：switch 分发 → 递归调用 exec → 环境链线性查
变量。JIT 把整段函数体**一次性**翻译成原生指令，运行期只剩纯寄存器/栈
操作，没有分发、没有查表。对递归/循环密集的程序提升一个数量级以上。

## 二、可 JIT 判定（jit_analyze.h）

`jit_plan_function` 对每个函数做静态分析，全部满足才标记可 JIT：

1. **节点白名单**：只允许 N_NUM/N_IDENT/N_BINARY/N_CALL/N_VAR/N_ASSIGN/
   N_IF/N_WHILE/N_RETURN/N_BLOCK；N_STR 仅允许作 `喵叫` 实参；
   N_ARRAY/N_INDEX 一律拒绝；
2. **引用检查**：所有 N_IDENT 必须是形参或函数内 `变量` 声明的局部变量，
   引用全局变量 → 拒绝；
3. **参数上限**：形参个数 ≤ 平台寄存器参数上限（Linux/SysV 为 6，
   Windows x64 为 4）；
4. **闭包传播**（jit.h）：函数 A 调用了不可 JIT 的 B → A 也不可 JIT，
   迭代到不动点（递归/互调链整体准入或整体出局）。

每个 FnPlan 记录拒绝原因（reject_reason），DEBUG 构建下打印出来。

## 三、变量编号与寄存器映射

分析阶段给每个变量（形参 + 局部）分配连续 vreg 号，临时值按表达式结构
续编——**计数顺序与代码生成顺序严格一致**，两边不会错位。

vreg 到物理寄存器是**固定映射**（不做图着色），Linux x86-64：

```
JIT_VREG_TO_PHYS = { RAX, RBX, R12, R13, R14, R15, RSI, RDI, RDX,
                     RCX, R8, R9, R10, R11 }
  v0  = RAX   结果累加器（返回值也走它）
  v1~v6 形参（序言里从 ABI 参数寄存器 RDI/RSI/RDX/RCX/R8/R9 拷入）
  v7~v13 其余临时/局部
  v14+ 溢出：放栈槽 [rbp - k*8]，不再占寄存器
```

Windows x64 映射不同（4 个参数寄存器 RCX/RDX/R8/R9、调用方预留 32 字节
shadow space、callee-saved 多含 RDI/RSI），由 `#ifdef _WIN32` 切换。

## 四、帧布局（序言/尾声）

```
序言                          尾声
push rbp                      add rsp, frame_bytes
mov  rbp, rsp                 pop callee-saved…（逆序）
push 用到的 callee-saved      pop rbp
sub  rsp, frame_bytes         ret
xor  eax, eax                 ← 无显式返回时默认返回 0
拷贝形参 ABI 寄存器 → v1..vP
```

- callee-saved（RBX、R12~R15）被映射占用就必须 push/pop 保护；
- **16 字节栈对齐**：call 进入时 RSP ≡ 8 (mod 16)，据此反推
  `(pushed_bytes + frame_bytes) ≡ 8 (mod 16)` 的帧大小；
- 含调用/打印/除模的函数额外分配 **caller-saved 快照槽**
  （RSI/RDI/RDX/RCX/R8~R11 各 8 字节）：调用前把活跃值快照进槽，
  调用后恢复——因为被调用方可以随意破坏这些寄存器。

## 五、两遍编译与函数地址表

```
jit_compile_all(fn_table)
  ├─ jit_alloc_exec(1MB)     mmap 匿名 RWX 可执行内存（代码缓冲）
  ├─ 第一遍：逐个 plan + 闭包传播
  ├─ 占位：可 JIT 函数在 g_jit_table[i] 写非零哨兵
  │         （编译期引用目标时槽位已存在 → 递归/互调可行）
  └─ 第二遍：逐个发射机器码，真实地址写回 g_jit_table[i]
             与 fn->jit_addr / fn->jittable
```

生成的代码**不直接 call 别的函数地址**，而是：

```
movabs rax, g_jit_table 地址
mov    rax, [rax + 下标*8]     运行期查表取目标入口
call   rax
```

所以先编译 fib、后编译它递归引用的自己，完全没问题。

## 六、表达式 → 机器码（jit_codegen.h）

统一约定「求值结果放进 dst vreg」：

- 数字：`mov reg, imm32`（大数 movabs imm64）；
- 变量：vreg 间 `mov`（源在溢出槽则 `mov reg, [rbp-off]`）；
- 二元运算：左操作数进 RAX，右操作数直读寄存器或内存：
  - `+ - *` → `add/sub/imul rax, src`；
  - `/` `%` → 先快照 caller-saved → `cqo` + `idiv` → 商在 RAX、余数在
    RDX（取模再 `mov rax, rdx`）→ 恢复快照；
  - 比较 → `cmp` + `setcc al` + `movzx`（结果恒为 0/1）；
- 调用：实参装入 ABI 参数寄存器（caller-saved 源从快照槽读）→
  表间接 call → 结果从 RAX 存回 dst。

## 七、函数内喵叫

字符串字面量集中放在 JIT 数据区（`jit_lit_addr` 判重后追加），
机器码里直接 `movabs rdi, 字面量地址`。整数实参先经 `jit_itoa`
格式化到全局 scratch 缓冲再打印：

```
jit_print(msg, endl)   #no_mangle extern "C"，fputs ×2
  endl = "\n"（末参） 或 ""（非末参，无分隔符）
```

输出规则与解释器逐字节一致：参数间无分隔符、末尾换行。

## 八、调用点分流与平台回退

```
exec_call()
  ├─ f->jittable？ → jit_invoke(f, arg_vals, nargs)
  │     实参 Value.num 取出补齐成 6 个 int64
  │     函数指针直接调用（SysV/Win64 ABI）
  │     返回 int64 包回 num_val
  └─ 否则继续树遍历解释
```

- 非 x86-64/x64 平台：`jit_plan_function` 直接把所有函数判为不可 JIT
  （平台不支持），等效于纯解释器运行；
- JIT 内除 0 由 CPU 触发异常终止进程（解释器路径会正常报错，
  见 05-错误处理.md）；
- 机器码缓冲固定 1MB 不释放，进程退出由操作系统回收。
