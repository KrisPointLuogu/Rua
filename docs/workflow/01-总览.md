# 工作流程 01 — 总览：一次运行的完整旅程

> 本篇是系列首篇：跟踪 `./rua example/example.rua` 从启动到退出的每一步，
> 给出整条流水线的全景图。后续五篇分别深入各阶段。
>
> 本系列描述 **Rust 版**（src/ 下的移植实现）；C 版（includes/*.h）另有对应系列。

## 一、流水线全景

```
$ ./rua example.rua [--debug] [--dump] [--no-jit]
      │
      ▼
┌──────────────────── run (main.rs) ────────────────────────┐
│                                                           │
│  解析命令行（顺序无关）：                                  │
│    --debug --dump --jit/--no-jit -h + 文件路径            │
│      │                                                    │
│  read_file(path) ─────────── 源码读入（校验 UTF-8）       │
│      │                                                    │
│  lex_all(&src) ───────────── 词法分析 → Vec<Token>        │
│      │                                                    │
│  Parser::parse_tokens(toks) ─ 语法分析 → (prog, fns)      │
│      │   顶层 喵 … 收进 fns；其余语句收进 prog            │
│      ▼                                                    │
│  Runtime::build(&fns, jit_enabled) ── 预编译快路径        │
│      │   vm::compile_functions ── 可 VM 函数 → 字节码     │
│      │   jit::compile_functions ── 可 JIT 函数 → 机器码   │
│      ▼                                                    │
│  rt.run(&prog) ───────────── 解释执行                     │
│      │   顶层语句在全局环境逐条求值                       │
│      │   函数调用三层分流：                               │
│      │     可 JIT 且开启 → jit::invoke   （机器码）       │
│      │     可 VM            → vm::invoke    （字节码）    │
│      │     其余             → 树遍历解释                  │
│      ▼                                                    │
│  Ok(()) ──────────────────── 正常退出；Err(e) 则          │
│                              stderr 打印「第 N 行：消息」 │
│                              并 exit(1)                   │
└───────────────────────────────────────────────────────────┘
```

与 C 版的两大结构差异：

- **调试是运行时开关**（`--debug`/`--dump`），不是编译期宏——同一个二进制
  想看就开，不想看就不开；
- **多了一层字节码 VM**：JIT 关闭或函数不可 JIT 时先尝试 VM，
  VM 也不行才走树遍历解释。三层输出保证逐字节一致。

## 二、三种执行档位

| 档位 | 进入条件 | 形态 |
| --- | --- | --- |
| JIT | 默认；可 JIT = 可 VM && 参数 ≤6 && Linux x86-64 | x86-64 机器码 |
| 字节码 VM | `--no-jit`，或不可 JIT 但可 VM | 栈机字节码循环 |
| 树遍历解释 | 不可 VM（含字符串运算、数组、全局引用等） | exec() 递归求值 |

判定共享一个入口 `vm::scan_function()`（见 04-快路径.md），
预编译在 `Runtime::build` 里一次完成，运行期分流只查表。

## 三、模块地图

```
src/
  main.rs      入口：CLI 解析、read_file、流水线串联、错误收尾
  ast.rs       Node 枚举、RuaError{line,msg}、Result 别名
  lexer.rs     词法分析：源码 → Vec<Token>（char 码点迭代）
  parser.rs    语法分析：递归下降 + 优先级爬升 → AST
  runtime.rs   运行时：Value/Env/Ctx、exec 解释器、二元运算、三层分流
  vm.rs        字节码 VM：scan 判定、compile_functions、栈机 invoke
  jit.rs       x86-64 JIT：手写机器码发射、两遍编译、invoke
  debug.rs     --debug/--dump 输出：Token/AST/函数表/字节码/计时
```

单 crate 零第三方依赖（纯 std）。模块间依赖方向：
main → {lexer, parser, runtime, debug}；runtime → {vm, jit}；
vm 与 jit 共享 scan_function 判定。

## 四、错误处理模型

C 版用「error_at 打印即 exit」；Rust 版改为全链路 `Result<T, RuaError>`：

- 每层用 `?` 向上传播，`RuaError { line, msg }` 携带行号；
- main() 统一格式化「第 N 行：消息」到 stderr 并 `exit(1)`；
- 好处：运行时错误能带精确行号（C 版部分错误固定为第 0 行）。

详见 05-错误处理.md。

## 五、一次运行的耗时构成

`--debug` 时 stderr 打印三段计时（debug.rs 的 Timer）：

1. **VM/JIT 预编译** —— Runtime::build 的总时长（毫秒级）；
2. **运行时间** —— rt.run(prog) 的时长（真正的程序执行）；
3. 各阶段（读文件/词法/语法）也有独立计时点。

对计算密集型程序（如递归 fib(36)）：JIT 约 0.16s、VM 约 3s、
树遍历解释约 7s——三层差距一个数量级。
