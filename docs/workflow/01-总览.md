# 工作流程 01 — 总览：一次运行的完整旅程

> 本篇是系列首篇：跟踪 `./rua example/example.rua` 从启动到退出的每一步，
> 给出整条流水线的全景图。后续五篇分别深入各阶段。

## 一、流水线全景

```
$ ./rua example.rua
      │
      ▼
┌────────────────────── main (rua.c) ──────────────────────┐
│                                                          │
│  read_file(path) ──────────── 源码读入内存（\0 结尾）     │
│      │                                                   │
│      ▼                                                   │
│  compile(src) ─────────────── 编译：源码 → AST           │
│      │   lex_all()          词法分析 → Token 数组        │
│      │   循环直到 TK_EOF:                                │
│      │     喵 …  → parse_function() → register_fn()      │
│      │            （函数注册进 fn_table，不进程序体）    │
│      │     其余  → parse_statement() → prog->stmts       │
│      ▼                                                   │
│  debug_dump_bytecode(prog) ── [仅 DEBUG] 静态字节码转储  │
│      │                                                   │
│      ▼                                                   │
│  jit_compile_all(fn_table) ── [仅 OPTIMIZATION]          │
│      │                        把可 JIT 函数编译成机器码  │
│      ▼                                                   │
│  exec(prog, &ctx) ─────────── 树遍历解释执行             │
│      │   顶层语句在全局环境逐条求值                      │
│      │   函数调用时：可 JIT → jit_invoke() 走机器码      │
│      │             其余   → 继续解释                     │
│      ▼                                                   │
│  return 0 ─────────────────── 正常退出（错误则 exit(1)） │
└──────────────────────────────────────────────────────────┘
```

要点：

- **编译期**只做词法 + 语法，不做语义检查、不生成中间代码；
  函数定义在编译期就注册进全局函数表 `fn_table`（runtime.h）。
- **运行期**以树遍历解释为主干；JIT 是函数级的加速旁路——
  只有「可 JIT」的纯整数函数才被编译成机器码，其余照常解释。
- 所有调试输出走 stderr，程序输出（喵叫）走 stdout，互不污染。

## 二、三种构建形态

| 构建命令 | 宏定义 | 行为 |
| --- | --- | --- |
| `make` | `-DOPTIMIZATION -DDEBUG` | JIT + 全部调试输出 |
| `make release` | `-DOPTIMIZATION` | JIT、无调试输出 |
| `make interp` | 无 | 纯解释器（无 JIT、无调试） |

- `OPTIMIZATION` 控制 JIT 是否参与构建（rua.c / runtime.h 里的 `#ifdef`）；
- `DEBUG` 控制调试输出与字节码转储是否编译进去（见 06-调试工具.md）。
- 非 x86-64/x64 平台即使定义了 `OPTIMIZATION`，JIT 也会在运行期自动跳过，
  全部函数回退解释执行（见 04-快路径.md）。

## 三、模块地图

```
rua.c                主入口：read_file / compile / main
includes/
  utf8.h             UTF-8 码点工具 + error_at 统一报错出口
  lexer.h            词法分析：源码 → Token
  ast.h              AST 节点定义（通用 Node，kind 区分）
  parser.h           语法分析：Token → AST（递归下降 + 优先级爬升）
  runtime.h          运行时：Value/Env/Ctx、exec 解释器、二元运算表
  bytecode.h         [DEBUG] 静态 AST → 字节码文本转储
  debug_process.h    [DEBUG] 调试输出与计时（printk 风格封装）
  jit.h              JIT 入口：两遍编译 jit_compile_all + 分发 jit_invoke
  jit/
    jit_base.h       寄存器/平台常量、打印辅助、可执行内存、Jit 状态
    jit_emit.h       x86-64 指令发射器与标签回填
    jit_analyze.h    变量表、可 JIT 判定、帧布局
    jit_codegen.h    表达式/语句 → 机器码
    jit_debug.h      [DEBUG] JIT 反汇编与调用轨迹
```

头文件即实现（无 .c 文件），rua.c 按 include 顺序把各模块「串」成一个
翻译单元。include 顺序即依赖顺序：utf8 → lexer/ast → parser → runtime →
debug/bytecode → jit。

## 四、一次运行的耗时构成

`make`（DEBUG 构建）运行时会在 stderr 打印三段计时（`DBG_TIMED` 宏）：

1. **编译** —— lex_all + parse 的总时长（毫秒级）；
2. **JIT 编译** —— 可 JIT 函数生成机器码的时长（毫秒级）；
3. **用户源码运行时间** —— exec(prog) 的时长（真正的程序执行）。

对计算密集型程序（如递归 fib），第 3 段在 JIT 版下比纯解释版快一个数量级
以上；编译与 JIT 编译本身是一次性的固定开销。
