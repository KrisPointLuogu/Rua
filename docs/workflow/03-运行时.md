# 工作流程 03 — 运行时

> AST 如何被解释执行：值系统、环境链、exec 分发循环、函数调用与三层分流。
> 涉及 src/runtime.rs（快路径细节见 04-快路径.md）。

## 一、值系统：Value 枚举

```rust
pub enum Value {
    Num(i64),
    Str(Rc<String>),                     // 引用计数共享
    Arr(Rc<RefCell<Vec<Value>>>),        // 句柄共享 + 内部可变
}
```

- **字符串**：`Rc<String>` 克隆只加引用计数，拼接时才分配新串；
- **数组是句柄语义**：赋值/传参共享同一个 `Rc<RefCell<Vec>>`——
  `b = a` 之后 `a[0] = 9` 则 `b[0]` 也是 9；
- `print_val(v)`：数字十进制、字符串原样、数组打印字面量「数组」。

## 二、环境链：Env

```rust
pub struct Env {
    parent: Option<Rc<RefCell<Env>>>,
    bindings: Vec<Binding>,      // Binding { name, val }
}
```

- 作用域就是一条 parent 链：全局环境 parent=None，
  每次函数调用新建子环境挂到调用者环境下；
- `env_get(e, name)`：沿链由内向外逐层线性查找，找不到报错
  （错误带行号）；
- `env_set(e, name, v)`：沿链找到即改；**各层都没有则在当前层新建**
  （隐式声明）；
- `env_bind(e, name, v)`：在指定层追加绑定（声明/形参用）。

内存管理差异：C 版用空闲链表复用 Env/Binding；Rust 版靠
`Rc` 引用计数自动释放——子环境出作用域引用归零即回收，无需手工池化。

## 三、求值上下文 Ctx 与返回传递

```rust
pub struct Ctx { env: Rc<RefCell<Env>>, returning: bool, retval: Value }
```

返回语句靠标志向上传递：

1. `Node::Return` 求值后置 `ctx.returning = true`，retval 存返回值；
2. `Block` / `Prog` / `While` 每执行完一条语句就检查该标志，
   为真立即停止；
3. `exec_call` 看到标志后取 `retval` 作为调用结果。

## 四、解释主循环：exec()

`rt.exec(n, ctx)` 按 Node 变体 match 分发，返回表达式求值结果：

```
Num       → Value::Num(val)
Str       → Value::Str(Rc 克隆)
Ident     → env_get(ctx.env, name)
Var       → 求初值 → env_bind 当前层          （声明即绑定）
Array     → 求广播初值 → Vec 填充 len 份 → env_bind
Assign    → 求右值 → 写目标：
              Ident → env_set；Index → 数组元素写入（越界报错带行号）
Index     → 求基址+下标 → 越界检查 → 读元素
Binary    → 求左、求右 → apply_binop(op, a, b, line)
Call      → exec_call(n, ctx)                 ← 函数调用入口
If        → 条件真执行 then_blk，否则执行 else_blk（可空）
While     → 循环「条件→体」，体执行后检查 returning 提前退出
Return    → 置 returning/retval
Func      → Num(0)（函数定义已在编译期注册，运行期遇到直接跳过）
Prog/Block→ 逐条执行，returning 时提前结束，返回最后一条的值
```

条件判断 `is_true(v)`：数字非 0 为真、字符串非空为真、数组恒为真。

## 五、二元运算：apply_binop

按 TokenKind match 分发（C 版是函数指针表，语义一致）：

| 运算 | 类型规则 |
| --- | --- |
| `+` | 任一侧是字符串 → 另一侧转文本做拼接；否则数字相加 |
| `-` `*` `/` `%` | 只接受数字；除数/模数为 0 报错（**带行号**） |
| `==` `!=` | 双字符串比内容；双数字比数值；类型不同视为不等 |
| `>` `<` `>=` `<=` | 只接受数字 |

类型错误全部返回 `Err(RuaError)` 向上传播，不再直接 exit。

## 六、函数调用：exec_call() 与三层分流

```
exec_call(rt, n, ctx)
  ├─ name == "喵叫"？
  │    ├─ 逐实参：求值 → print_val 立即打印（参数间无分隔符）
  │    ├─ 全部打完 → println!()
  │    └─ 返回 Num(0)
  ├─ find_fn(&rt.fns, name)             找不到 → Err(未定义的函数)
  ├─ 形参个数校验（不匹配报错）
  ├─ 先求值全部实参
  ├─ ① f.jit 且 rt.jit_enabled？ → jit::invoke(&rt.jit, idx, 实参.num)
  │     返回 i64 包回 Num                        ← 默认快路径
  ├─ ② f.vm？ → vm::invoke(&rt.vm, idx, 实参.num)
  │     返回 Result<i64> 包回 Num                ← --no-jit 或不可 JIT
  ├─ ③ 树遍历解释：
  │     新建子环境绑形参 → 子 Ctx 执行函数体 → 回收
  └─ 返回 returning ? retval : 函数体最后一条语句的值
```

要点：

- **实参先全部求值再进入被调函数**（求值顺序即书写顺序）；
- 三层输出保证逐字节一致（喵叫 打印规则、除 0 报错文案等均对齐）；
- 无显式 `返回` 的函数：JIT/VM 层返回 0，解释层返回函数体最后一条
  语句的值——可 VM/JIT 的函数必然有显式返回或以表达式结尾的差异
  已在判定层对齐（见 04-快路径.md）；
- 递归/互调没有特殊处理——每层各自支持递归（JIT 经地址表间接调用、
  VM 经帧栈、解释经递归 exec_call）。

## 七、喵叫 打印规则

- 参数逐个**求值一个打印一个**（不是先全求值再打印）——
  所以出错时前面的参数已经打出去了；
- 参数之间**无分隔符**：`喵叫(10,20)` 输出 `1020`；
- 结尾固定换行：输出为 `1020\n`；
- 数组实参打印「数组」二字；字符串原样；数字十进制。
