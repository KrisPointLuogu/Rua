# 工作流程 06 — 调试工具

> 两个编译期宏（`DEBUG`、`OPTIMIZATION`）控制三套观测手段。
> 涉及 includes/debug_process.h、includes/bytecode.h、includes/jit/jit_debug.h。

## 一、双开关总览

| 宏 | 控制什么 | 打开方式 |
| --- | --- | --- |
| `DEBUG` | 全部调试输出 + 字节码转储 + 计时 | `make`（默认带） |
| `OPTIMIZATION` | JIT 参与构建与调用分流 | `make` / `make release` |

| 构建 | DEBUG | OPTIMIZATION | 效果 |
| --- | --- | --- | --- |
| `make` | ✓ | ✓ | 调试输出 + JIT |
| `make release` | ✗ | ✓ | 静默 + JIT |
| `make interp` | ✗ | ✗ | 静默 + 纯解释 |

关键设计：**宏关闭时调试函数展开为空实现**，零运行时开销；
计时器类型始终编译进去，配合 `DBG_TIMED` 宏使用。

## 二、debug_process.h：输出与计时

printk 风格的封装层，所有输出带 `[调试]` 前缀走 stderr：

- `debug_print(fmt, …)` —— 基础打印；模块标签由调用方写进格式串
  （如 `[LANG] `、`[JIT] `）；
- `DBG_TIMED(label, stmt)` —— 计时宏：执行语句并打印耗时。
  main 里包了三段：编译 / JIT 编译 / 用户源码运行时间
  （Windows 用 QueryPerformanceCounter，POSIX 用 clock_gettime）；
- 结构化转储：
  - `debug_dump_tokens()` —— Token 流逐个「行号:类型:文本」；
  - `debug_print_stmts()` —— 顶层语句列表（node_kind_name 中文节点名）；
  - `debug_print_fns()` —— 函数表（名字/形参/是否可 JIT）。

## 三、bytecode.h：静态字节码转储

`debug_dump_bytecode(prog)` 把 AST **静态翻译**成类 Python dis 的助记符
指令流（不执行、不求值、不折叠常量），输出到 stderr：

```
LOAD_CONST  <idx>      常量表第 idx 项压栈（数字/字符串）
LOAD_NAME   <idx>      符号表变量压栈
STORE_NAME  <idx>      弹栈存入符号表
NEW_ARRAY   <len>      弹初值建数组压栈
LOAD_INDEX / STORE_INDEX   数组读写
ADD/SUB/MUL/DIV/MOD/EQ/…   二元运算（弹右弹左压结果）
CALL_FN     <name> <n> 用户函数调用
CALL_BUILTIN <name> <n> 内置（喵叫）
MAKE_FUNCTION <name> <n> 函数声明（不执行体）
JUMP / JUMP_IF_FALSE L<pc> 控制流（伪 label）
RETURN_VALUE            返回
```

- 常量表/符号表去重，指令用下标引用；pc 全局连续递增；
- 主程序语句在前，随后每个函数一段（`; --- 函数 xxx ---` 分隔）；
- 用途：观察程序结构、对照解释流程，不是可执行的真正字节码。

## 四、jit_debug.h：JIT 观测（DEBUG + OPTIMIZATION）

JIT 编译与运行期间输出的三组信息：

1. **判定日志**：每个函数「可 JIT / 不可 JIT（原因）/ 解释执行」，
   拒绝原因来自 FnPlan.reject_reason；
2. **编译详情**：入口地址、机器码字节数、vreg 使用统计、帧布局
   （pushed/frame/快照槽）、callee-saved 列表、变量→vreg 表、调用列表；
3. **反汇编转储** `jit_dump_disasm()`：把生成的机器码按 x86-64 逐条
   解码成 `偏移  字节  助记符 操作数` 文本——手写发射器的正确性就靠它人肉验证；
4. **调用轨迹** `debug_log_jit_invoke()`：每次解释器 → JIT 调用的
   实参与返回值。

## 五、典型调试会话

```console
$ make                       # DEBUG + JIT
$ ./rua example/example.rua > out.txt
[调试] [LANG] 读取文件：example/example.rua（xxx 字节）
[调试] Token: ...
[调试] [main] 编译：0.385 ms
...字节码转储...
[调试] [JIT] 函数[0] fib → 可 JIT
[调试] [JIT] 编译函数[0] fib → 地址=0x... 机器码=444 字节
[调试]   机器码 汇编:
[调试]   0000  55    push RBP
...
[调试] [main] 用户源码运行时间：0.013 ms
$ cat out.txt                # 程序自己的输出，干净无调试信息
```

定位思路：

- 词法/语法问题 → 看 Token 转储与 AST 打印；
- 「为什么没走 JIT」→ 看判定日志里的拒绝原因；
- 机器码算错 → 对照反汇编与 jit_codegen.h 的发射序列；
- 性能问题 → 对比三段 DBG_TIMED 计时。
