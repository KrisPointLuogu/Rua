# 工作流程 06 — 调试工具

> C 版靠编译期宏（-DDEBUG）开关调试；Rust 版全部改为**运行时参数**
> `--debug` / `--dump`，同一个二进制随时开关。涉及 src/debug.rs 与 main.rs。

## 一、开关总览

| 参数 | 输出去向 | 内容 |
| --- | --- | --- |
| `--debug` | stderr | Token 明细、AST、函数表（JIT/VM 状态）、各阶段耗时 |
| `--dump` | stderr | 可 VM 函数的字节码反汇编文本 |
| （默认无） | stdout | 只有程序自己的输出 |

- 调试输出全部走 stderr，程序输出（喵叫）走 stdout，可自由重定向；
- 参数顺序无关：`rua a.rua --debug` 等价 `--debug a.rua`。

## 二、debug.rs 提供的转储

### 2.1 dump_tokens —— 词法明细

逐 Token 打印「行号:类型:文本」，与 C 版 debug_dump_tokens 对应：

```
[00] 行3   变量
[01] 行3   标识符  文本=a
[02] 行3   赋值=
...
```

### 2.2 dump_prog / dump_node —— AST 树

缩进文本树，节点用中文名（变量声明/二元运算/函数调用…），
对应 C 版 debug_print_stmts 但更细：整棵 AST 递归打印。

### 2.3 dump_functions —— 函数表与快路径状态

```
函数 阶乘（形参 ["n"]）→ JIT [0] / VM [0]
函数 计数（形参 ["k"]）→ JIT [1] / VM [1]
函数 打印循环（形参 ["n"]）→ JIT [2] / VM [2]
```

每个函数一行：JIT 索引（未 JIT 显示原因/已关闭）、VM 索引
（不可 VM 显示「解释」）。一眼看出哪些函数走了哪层快路径。

### 2.4 dump_bytecode —— 字节码反汇编

把 VmEngine 里每个可 VM 函数的指令序列翻译成助记符
（对应 C 版 bytecode.h 的静态转储，但这里是**真正执行的字节码**）：

```
== 函数 阶乘 ==
  0   load v0
  1   push 1
  2   le
  3   jz 8
  ...
```

## 三、计时器 Timer

```rust
Timer::new("VM/JIT 预编译")   // 构造时开始计时
drop(build_t);                // drop 时打印「[调试] VM/JIT 预编译：x.xxx 秒」
```

main.rs 埋了三段：VM/JIT 预编译、运行时间（另有读文件/词法等独立计时点）。
RAII 风格——离开作用域自动结算，不会忘记停表。

## 四、典型调试会话

```console
$ cargo build --release
$ ./target/release/rua example/example.rua --debug > out.txt
[调试] 读取文件：example/example.rua(685 字节)
[调试] Token: ...
[调试] 顶层语句（11 条）：...
[调试] VM/JIT 预编译：0.8 ms
[调试] 函数 fib（形参 ["n"]）→ JIT [0] / VM [0]
...
[调试] 运行时间：12.1 ms
$ cat out.txt                 # 程序自己的输出，干净无调试信息
a + b = 30
结果正确
...

$ ./target/release/rua example/example.rua --dump 2>&1 >/dev/null | less
```

定位思路：

- 词法/语法问题 → 看 Token 转储与 AST 树；
- 「为什么没走 JIT」→ 看 dump_functions 的状态列
  （不可 JIT 会回退 VM，再不行才解释）；
- 字节码逻辑问题 → 对照 dump_bytecode 与 vm.rs 指令语义；
- 性能问题 → 对比各段计时；再配合 `--no-jit` 分层测量。
