# 虚拟机执行是怎么生成的？

## 输入

`BytecodeProgram`（来自字节码生成）。

## 输出

程序执行结果（标准输出）。

## 架构

```
值栈 (stackData)     — Value[] 预分配数组，_sp 为栈顶指针
调用栈 (callStackData) — int[] 预分配数组，保存返回地址
帧栈 (frameStackData)  — int[] 预分配数组，保存每层函数调用的帧基址
指令指针 (ip)          — 当前正在执行的字节码位置
栈顶缓存 (_tos)        — Value 变量，始终与 s[_sp] 同步
```

## 执行流程

`VM::run(prog)` 执行以下步骤：

### 1. 初始化

```cpp
_sp = -1;        // 值栈空
_cp = -1;        // 调用栈空
_fp = -1;        // 帧栈空
s = stackData.get();  // 预分配数组指针
_tos = {0};      // 栈顶缓存
```

### 2. 指令分发

使用 **直接线程分发**（computed goto）：`static void* dispatch[]` 跳转表 + `goto *dispatch[code[ip]]`，比 `switch` 减少分支预测开销。

### 3. 关键优化

| 优化 | 说明 |
|------|------|
| 预分配数组 | 避免 `vector` 容量检查和重分配 |
| 栈顶缓存 | `_tos` 始终镜像 `s[_sp]`，高频操作直接读写寄存器 |
| 超级指令 | `SUB_ICONST` / `GT_ICONST` 合并 `ICONST + SUB/GT` 为一条指令，省一次分发 |
| 叶子函数快速路径 | 检测到函数不含 CALL 时跳过帧栈/调用栈操作，直接执行函数体 |
| 8 字节 Value | `Value` 为 `{type, data}` 联合体，无 `string` 堆分配开销 |

### 4. 调用约定

```
CALL funcIdx:
    frameBase = _sp + 1 - func.paramCount
    pushFrame(frameBase)          // 保存帧基址
    pushInt(0) × func.localCount  // 分配局部变量
    pushCall(ip + 4)              // 保存返回地址
    ip = func.codeOffset          // 跳转到函数体

RET:
    retVal = pop()
    _sp = popFrame() - 1          // 回收栈空间
    push(retVal)                  // 保留返回值
    ip = popCall()                // 恢复返回地址
```

### 5. 叶子函数快速路径

当 `func.isLeaf == true` 时，CALL/RET 不操作帧栈和调用栈，直接保存/恢复基址和返回地址到局部变量，减少内存访问。

## 指令集

| 操作码 | 指令 | 说明 |
|--------|------|------|
| 0x00 | HALT | 程序终止 |
| 0x01 | ICONST | 压入整数常量 |
| 0x02 | SCONST | 压入字符串常量 |
| 0x03 | ADD | 弹出两值相加 |
| 0x04 | SUB | 弹出两值相减 |
| 0x05 | MUL | 弹出两值相乘 |
| 0x06 | DIV | 弹出两值相除 |
| 0x07 | EQ | 比较相等 |
| 0x08 | JMP | 无条件跳转 |
| 0x09 | JIF | 条件跳转 |
| 0x0A | LOAD | 加载局部变量 |
| 0x0B | STORE | 存入局部变量 |
| 0x0C | CALL | 调用函数 |
| 0x0D | PRINT | 输出栈顶值 |
| 0x0E | RET | 函数返回 |
| 0x0F | POP | 丢弃栈顶 |
| 0x10–0x13 | LT/GT/NEQ/MOD | 比较和取模 |
| 0x14–0x15 | SUB_ICONST/GT_ICONST | 超级指令 |
